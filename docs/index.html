Google Search Ranking & Discoverability Capstone

CTR / Engagement Opportunity Scoring

Research question: Which visible pages under-capture clicks or engagement and deserve metadata, content, or monitoring review? Decision supported: Which pages should an SEO/content reviewer investigate first? Lane: CTR / Engagement Opportunity Scoring

Abstract

Search teams need a practical way to decide which visible pages deserve review first. This capstone studies CTR / Engagement Opportunity Scoring using pseudonymized FlyRank search-performance data and a page-level ranking approach. The warehouse contains 78,835,655 daily performance rows in the documented release, while the executed notebook connection returned 7,883,565 rows for the queried local slice. A preliminary modeling run produced a baseline MAE of 0.012917 and model MAE of 0.000016, but that run is explicitly treated as invalid evidence because the model inputs included clicks and impressions while the target was CTR, which is directly derived from those fields. Therefore this paper reports the preliminary numbers for reproducibility only and does not claim model superiority until a leakage-safe future-window evaluation is executed.

1. Introduction / Problem statement

Search visibility alone does not tell a reviewer which page deserves attention first. A page can receive meaningful search exposure while capturing fewer clicks than comparable visible pages. The goal of this project is therefore decision support: rank pages for human review using observable search and engagement signals, rather than claiming that a score guarantees a successful SEO change.

The intended user is an SEO or content reviewer with limited review capacity. The output is a ranked queue with an action and a reason code.

The documented warehouse release is `flyrank_pseudonymized_warehouse_release_v20260703`.

Public output excludes client names, domains, raw URLs, private queries, titles/text that could reveal a client, credentials, and internal infrastructure details.

3. Methodology

Unit of analysis

A page-level search-performance observation for a pseudonymized client and content item at a reporting date.

Candidate decision-time features

The intended CTR/engagement feature family includes:

  • GSC impressions
  • GSC clicks
  • CTR
  • average position
  • position tier
  • content type / intent where safely available
  • content age / freshness where safely available
  • sessions
  • engagement context

Opportunity logic

CTR must be interpreted relative to search visibility and position. Pages at different positions naturally have different click-through behavior, so a useful opportunity score should compare a page against an appropriate position/visibility context rather than apply one global CTR threshold.

Baseline

The baseline is a transparent rule/ranking approach using observable visibility and CTR context. Reason codes are intended to make the queue inspectable by a human.

Validation

The final capstone requires a time-aware future-window design: features measured at month *t* must predict an outcome in month *t+1*. A leakage audit must confirm that the target window does not enter the feature window and that derived target fields are excluded.

4. Results vs baseline

Preliminary executed run

The first executed modeling run reported:

| Metric | Result | |---|---:| | Baseline MAE | 0.012917 | | Model MAE | 0.000016 | | Apparent improvement | 0.012902 |

Leakage finding

These numbers are not used as evidence of model quality.

The preliminary code predicted CTR while supplying `gsc_clicks` and `gsc_impressions` as model inputs. Because CTR is directly computed as clicks divided by impressions, those features contain the answer itself. The near-zero model error is therefore a leakage artifact.

This is precisely the type of failure the capstone's leakage audit is designed to catch. The documented project guidance says that target-window metrics must not be used as features and that a feature derived from the answer can make results look great while being worthless.

A leakage-safe run is required before claiming that a learned model beats the baseline.

5. Limitations & honest framing

This work is observational and intended for decision support.

A low CTR does not prove that a title, metadata element, or page content is defective. Search intent, SERP features, seasonality, brand/non-brand mix, and other factors can affect observed CTR.

A ranked opportunity score does not prove that changing a page will cause a recovery. Establishing causal refresh impact would require an appropriate experiment or causal design.

The preliminary result demonstrates why leakage control matters; it does not demonstrate production model performance.

6. Ranked recommendations

The action engine should prioritize pages using transparent evidence and provide one reason code per recommendation.

Recommended action categories:

1. **REVIEW_CTR_METADATA** — visible page with meaningful exposure and CTR weakness relative to its position context.

2. **REVIEW_INTENT_MATCH** — CTR weakness where search intent/content alignment deserves human inspection.

3. **REVIEW_ENGAGEMENT** — meaningful sessions with weak engagement signals.

4. **MONITOR** — directional weakness without enough evidence for an immediate content change.

Human reviewers should inspect the highest-ranked candidates before changing titles, metadata, content, consolidation status, or publication state.

The score should never be treated as an automatic publishing command.
